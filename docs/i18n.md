# Internationalization (i18n)

> Extracted from `design/ui-i18n-design.md` for developer reference.
> The full design document with future plans remains at `design/ui-i18n-design.md`.

---

## Current State

dtui supports `en` (English) and `zh` (Simplified Chinese), plus compatibility forms `zh-CN` / `zh_CN`.

Translation files live under `internal/data/i18n/lang/`:

```
lang/
├── en.jsonc   # English (default)
├── zh.jsonc   # Simplified Chinese
└── ja.jsonc   # Japanese (partial)
```

Each file is a flat key → string map with `{0}`, `{1}` placeholders for arguments. Comments (`//` and `/* */`) are allowed and stripped at load time via `internal/utils/jsonc.go`.

## Configuration

Set the active language via:

1. CLI flag: `--lang zh` or `--lang en`
2. Config file: `general.lang: zh`
3. Environment variable: `LANG`

Missing keys fall back to English and never panic.

## Adding a New Language

1. Copy `en.jsonc` to `lang/<code>.jsonc`
2. Translate each value
3. Add the language code to the `tags` map and `parseTag` switch in `internal/data/i18n/lang.go`
4. Rebuild

## Design Principles

### 1. Keys vs Display Text Separation

- Data model names, action IDs, command names, and runtime names stay in English — they are not translated.
- UI rendering layer uses `i18n.T(key, args...)` for all user-facing text.
- Translated text is never used for state checks, sort keys, or event branching.
- Missing translations return the key name explicitly (detectable in dev/test).

### 2. Terminal Cell Width, Not Rune Count

Chinese characters occupy 2 terminal columns but count as 1 rune. All layout calculations must use terminal cell width:

```go
func DisplayWidth(s string) int       // terminal columns occupied
func TruncateDisplay(s string, width int) string
func PadDisplay(s string, width int) string
```

Must handle: ANSI escape sequences, CJK wide characters, fullwidth punctuation, combining/zero-width characters, and post-truncation style closing.

### 3. Container Width Before Text Rendering

Each component follows this order:

1. Determine container width from terminal size and layout profile.
2. Calculate column widths, padding, and gaps using display width.
3. Truncate or wrap each text field.
4. Apply styles and colors last.

Translated text must never change parent track dimensions. If more space is needed, truncate, wrap, or switch to compact profile.

## Known Issues (Current State)

### Resource Parse Failures Masquerade as "No Change"

If `zh.jsonc` has a syntax error, `SetLang("zh")` succeeds but all keys fall back to English silently. The resource loader now returns diagnostic errors; production mode uses English fallback but preserves error state for startup messages and tests.

### `%-Ns` Padding Doesn't Account for CJK Width

`help/view.go` uses fixed `%-20s` for key columns. Chinese characters fill less visual space than English at the same Go string width. Help page should dynamically allocate key column + description column widths.

### Hardcoded English in Headers/Labels

`Search:`, `Filter:`, `Pull:`, `Terminal too small`, `Select a container...` etc. are hardcoded. These should be migrated to translation resources.

## i18n Key Groups

Resource keys are grouped by domain:

| Prefix | Domain |
|--------|--------|
| `panel.*` | Panel titles and labels |
| `table.*` | Table headers and status |
| `key.*` | Key descriptions |
| `hint.*` | UI hints |
| `dialog.*` | Dialog text |
| `msg.*` | Messages |
| `status.*` | Status bar text |
| `toast.*` | Notifications |
| `inspect.*` | Detail/inspect view labels |
| `detail.*` | Detail view titles |

## Docker Technical Terms

Docker technical terms stay in English — they are industry standard:

- ID, PID, CPU, IP, MAC, Port, Entrypoint, Cmd
- Container, Image, Volume, Network

Descriptive text is translated: section titles (Resources → 资源), prompts (Loading detail → 加载详情中...).

## Source View (Section/YAML/JSON)

Detail pages support three display modes toggled by `s`:

```
Section (default) → YAML → JSON → Section
```

| Mode | i18n Key Pattern |
|------|-----------------|
| Section | `detail.title.{resource}` |
| YAML | `detail.title.{resource}_yaml` |
| JSON | `detail.title.{resource}_json` |

Footer shows: `s:section y:yaml j:json` via `detail.source.hint`.

## Verification Criteria

- `--lang zh`, `--lang zh-CN`, and `general.lang: zh` display Chinese; `--lang en` restores English.
- Any translation resource parse failure must not silently show "switched but still English"; tests must locate the specific file and key.
- Chinese and English at the same terminal width must not produce column overlap, border misalignment, Footer overflow, or dialog over-width.
- All text truncation uses terminal display width; CJK characters counted by actual cell columns.
- Action branches, event handling, and audit use stable constants, not translation results.
